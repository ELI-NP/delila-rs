# TODO 87 — Monitor の rebin を ×1/×2/×4/×8 の 4 択にする

**Status: 🚧 実装・pf-qaq に配備 (2026-11-10、6289197、`git pull` だけ、DAQ は止めていない)。** 残 = ブラウザでの見え方の確認(開いているページは再読み込みが必要)。

## 1. 発端と今の作り(2026-11-10 にコードで確認)

- ユーザー: 「スライダの値が飛びすぎ」。
- 作り:
  - Monitor(サーバ)は 1 次元のエネルギーを 65536 ビン(1 ADC ch に 1 ビン)で持つ。画面が `utils/rebin.ts` で束ね直す。
  - View タブのスライダの値は「何ビンを 1 つにするか」の倍率で、範囲は 1 から `元のビン数 / 16` まで、1 刻みの等間隔。エネルギーでは 1〜4096 を幅 100 px で選ぶので、1 px で約 40 動き、1、2、4、8 はほぼ選べなかった。
  - 表示のビン数 = `65536 / 倍率` の切り捨て。
- ほかの問題:
  1. **櫛:** 割り切れない倍率(3、5、…)だと、表示のビン 1 つに入る元のビンが 3 つだったり 4 つだったりして、周期的なギザギザが出る。
  2. **範囲を狭めると壊れる:** 倍率は全範囲(65536)が基準だった。Setup で範囲を 0〜4096 にすると、倍率 1〜16 では表示のビンが 1 ch より細かくなり、ほとんど空の櫛になる。表示される倍率も実際と違う。
  3. **知らないうちに ×64:** Setup の「Bins」欄は、何もなければ既定の 1024 を表示していた(タブのほうの既定は元の 65536 = ×1)。範囲を変えて保存すると、その 1024 も一緒に保存される。pf-qaq の「PSD2-VX2730-LS Ch0-15」のタブが 1024 ビン(×64)だったのはこれで、**ユーザーも意図していなかった**(2026-11-10)。

## 2. 決定(ユーザー 2026-11-10)

- 「1、2、4、8 くらいまでは必須。16、32、64 は疑問。128〜4096 は正気を疑うレベル」→ **×1、×2、×4、×8 の 4 つだけにする。**
- LS のタブの ×64 は意図しないもの → 上限 ×8 でよい。

## 3. 実装

- **倍率をレイアウトに保存する**(`AxisView.rebin`、1/2/4/8)。実際のビン数は、グラフの部品が「表示範囲に入る元のビン数 ÷ 倍率」として、その都度計算する(`resolveRebinView`)。ADC でも keV でも同じ規則(keV の軸は元のビン数のまま尺度だけ変わる)。範囲を狭めても正しく、割り切れる倍率しか使わないので櫛も出ない。
- **前に保存されたレイアウトの `bins`** は、「元のビン数 ÷ bins」以下でいちばん大きい選択肢として読む(`rebinFactorOf`)。LS の 1024 → ×8(8192 ビン)、65536 → ×1。範囲より多いビン数(範囲を狭めた古いタブ)→ ×1。倍率を選び直すと `bins` は消えて `rebin` が入る(`withRebin`)。
- **割り切れない倍率は押せない。** 今の範囲の元のビン数を割り切れない倍率だけ無効にする。例えば元のビン数 1500 なら ×8 は押せない。データが来る前は 4 つとも押せる。
- **共通の部品** `components/rebin-picker/`(×1 ×2 ×4 ×8 のボタン、使用中の強調、ツールチップ「8192 bins, 8 native bins per bin」)。
  - **View タブ:** スライダの代わり。2 次元は X と Y。
  - **Setup:** 「Bins」の入力欄の代わり。
- **Setup の範囲の編集はビン数を保存しない**(上の 3 の原因を除いた)。軸の単位(ADC と keV)を切り替えたときも、倍率はそのまま残る。
- 2 次元(`heatmap-chart`)と拡大表示のダイアログは、同じ表示範囲の情報をグラフの部品に渡すので、どちらも同じ規則になる。
- 使わなくなったもの: スライダ、`MIN_DISPLAY_BINS`、`serverXBins`/`serverYBins`、`maxX/YRebinFactor`、Setup の `xBins`/`yBins` とその CSS。
