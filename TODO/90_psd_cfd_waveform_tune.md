## 1. 目的と決まったこと

| 項目 | 内容 |
|---|---|
| 目的 | ThGEM の 5 ch(トリガー + 遅延線の 4 本の腕)の CFD パラメーター(遅延、割合、平滑)を、**一度取った波形からソフトで走査して**決める |
| なぜオフラインか | ThGEM のイベントレートが低く、設定ごとにランを取る方式(HPGe の FW 側の走査)では時間がかかりすぎる(ユーザー)。波形を 1 回取れば、同じ波形に何百通りもの設定を当てられる |
| 波形の長さ | **500 サンプル = 1 µs**(2 ns)で足りる(ユーザーと一致) |
| 必ず守ること | record length は **1792 サンプル(3584 ns)未満**(UM4380 / UM5678: これ以上はカップル内で同時のイベントの片方を FW が捨てる。ThGEM の腕は同時に鳴るので致命的)。1 µs なら問題ない |
| 触らないもの | `cfd_interpolation_point` は 0 のまま(1 にすると 2 ns の櫛になる、PSD1 で実測済み)。閾値はこのツールでは決めない |

## 3. 方式

### 3.1 データ

1. **確かめ用:** パルサー(今つながっている V1730 の ch15 の TTL)、ThGEM が来たら ThGEM。
   - 2 本表示(Input + CFD)で、FW の CFD 波形とソフトの CFD を重ねて式を決める。
   - 1 本表示(Input、2 ns)で、イベントごとにソフトの時刻と FW の時刻(粗い時刻 + fine)を比べる。**目標: 差の RMS < 0.1 ns**。
2. **走査用:** ThGEM の 5 ch、1 本表示の Input、500 サンプル。pre-trigger はベースラインが取れる長さにする(案 100〜200 ns)。
   - 1 台あたり数千イベントあれば幅は出せる。

### 3.2 物差し

**遅延線の時間の和:** S_X = t_XL + t_XR − 2 t_T、S_Y = t_YU + t_YD − 2 t_T。
- 遅延線の全長で決まり、当たった位置によらず一定になるので、その幅(FWHM)が時間分解能そのものになる。正解の位置を知らなくてよい。
- 腕の選び方は thgem_sink と同じ(自分のトリガーに最も近い hit、`thgem_planes.hpp` の `nearest_in`)。
- ThGEM の役割は対応表から読む(`thgem_map.hpp`)。
- 補助の物差し: XY 像の格子(10 月は約 93 ns 周期)の鋭さ(後で)。

### 3.3 走査

- **遅延:** 2 ns 刻み(範囲の案 2〜60 ns、30 通り)。**割合:** 4 通り。**平滑:** 5 通り。→ 1 ch あたり 600 通り。
- 平滑は値ごとに 1 回だけ計算する。CFD は立ち上がりの前後 ±50 サンプルだけ計算する。数千イベント × 5 ch × 600 通りでも、マルチスレッドで数分以内の見込み。
- 順番: トリガーを固定して腕を最適化 → 腕を固定してトリガーを最適化 → 収束を確認(2〜3 周)。
- 結果:
  - ch ごとの最良値と物差しの値の表
  - 上位の候補の幅
  - V1730 の JSON の `channel_overrides` に当てる差分(適用は Tune Up か REST で)

### 3.4 実装

- **C++**(`tools/root_sink/thgem/` か `tools/cfd_tune/`)。部品が C++ に揃っているため:
  - `.delila` を読む部分 = `TDelila.hpp`(依存なし)
  - 対応表 = `thgem_map.hpp`
  - 腕の選び方 = `thgem_planes.hpp`
  - HPGe の `pha_trap_tune` は Rust だが、ThGEM の論理は C++ 側にある。
- 中身は ROOT を使わない純粋な関数にして、ヒストグラムの出力だけ ROOT を使う(任意)。
- **TDD:** 合成パルス(既知の立ち上がり、既知の時刻)で、ソフトの CFD の時刻・補間・平滑を単体テストする。テストは `test_thgem_sink.cpp` と同じ形式。

## 5. 気をつけること

- **FW の再現が少しでも違うと、走査の結果は意味がない。** P2 を通るまで P3 の結果は使わない。
- 時間の和を作るには 3 つの hit が全部要る(T と腕 2 本)。腕が欠けるイベントは物差しに入らない(欠ける割合は `narms` で見える)。
- 閾値は時刻に影響する(どこからゼロクロスを探すか)が、このツールでは動かさない。閾値を変えたら走査をやり直す。
- 波形を取るランは、データ量が増える(500 サンプル × 約 3 B = 約 1.5 kB/イベント)。ThGEM のレートなら問題ない。
